# Smart Employee Assistant

A Spring Boot 4, LangChain4j, Spring Data JPA, and MySQL demo. The LLM selects Java tools; only the Java tool implementations access employee data or change salaries.

## Package structure

```text
com.demo.sblangchain
├── assistant     LangChain4j assistant interface
├── config        LLM provider configuration and properties
├── controller    REST API controllers
├── dto           API and tool data-transfer objects
├── entity        JPA entities
├── repository    Spring Data JPA repositories
├── service       Application and business logic
└── tool          LangChain4j-callable Java tools
```

## What it can do

Send natural-language requests to `POST /api/assistant/chat`. The assistant has tools to:

- Find an employee by ID.
- List or count employees in a department.
- Compare average salaries between two departments.
- Increase an employee's salary (from greater than 0% through 100%).

The application exposes one HTTP endpoint for these requests:

```http
POST http://localhost:8086/api/assistant/chat
Content-Type: application/json
```

```json
{
  "sessionId": "demo-session",
  "message": "Find employee 101 and tell me their department"
}
```

`sessionId` is optional. Reuse it to continue a conversation; omit it to start a new one. The response is:

```json
{
  "sessionId": "demo-session",
  "answer": "Alice Johnson works in the Engineering department."
}
```

## API examples

The employee operations below are assistant tools, not separate REST routes. Each example calls `POST http://localhost:8086/api/assistant/chat`. The response `answer` is generated by the selected model, so exact wording can vary.

### Find employee by ID

```bash
curl -X POST "http://localhost:8086/api/assistant/chat" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"find-demo","message":"Find employee 101 and tell me their department and salary."}'
```

Example response:

```json
{
  "sessionId": "find-demo",
  "answer": "Alice Johnson works in Engineering and earns 92000.00."
}
```

### List employees by department

```bash
curl -X POST "http://localhost:8086/api/assistant/chat" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"list-demo","message":"List all employees in the Engineering department with their salaries."}'
```

Example response:

```json
{
  "sessionId": "list-demo",
  "answer": "Engineering employees: Alice Johnson (92000.00), Brian Smith (85000.00), and Carla Davis (98000.00)."
}
```

### Count employees by department

```bash
curl -X POST "http://localhost:8086/api/assistant/chat" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"count-demo","message":"How many employees are in Human Resources?"}'
```

Example response:

```json
{
  "sessionId": "count-demo",
  "answer": "There are 2 employees in Human Resources."
}
```

### Compare average salaries

```bash
curl -X POST "http://localhost:8086/api/assistant/chat" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"compare-demo","message":"Compare the average salaries of Engineering and Human Resources."}'
```

Example response:

```json
{
  "sessionId": "compare-demo",
  "answer": "The average salary is 91666.67 in Engineering and 70000.00 in Human Resources; Engineering is higher."
}
```

### Increase an employee's salary

```bash
curl -X POST "http://localhost:8086/api/assistant/chat" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"raise-demo","message":"Increase employee 101 salary by 10 percent."}'
```

Example response:

```json
{
  "sessionId": "raise-demo",
  "answer": "Alice Johnson's salary was increased by 10% from 92000.00 to 101200.00."
}
```

This request updates the database. Verify the resulting value with:

```sql
SELECT id, name, department, salary
FROM employees
WHERE id = 101;
```

The salary increase must be greater than 0% and no more than 100%. Do not repeat the example unless you intend to increase the salary again.

## Choose an LLM

Set exactly one provider's `enabled` flag to `Y` and leave the other providers at `N`. The enabled provider is selected automatically. Ollama is enabled by default and runs locally; make sure its service is running and the selected model is installed. Gemini and Groq default to `N`. Enabling more than one provider causes a configuration error.

### Gemini

```properties
assistant.llm.gemini.enabled=Y
assistant.llm.gemini.api-key=${GEMINI_API_KEY}
assistant.llm.gemini.model=gemini-3.8-flash
```

### Groq

```properties
assistant.llm.groq.enabled=Y
assistant.llm.groq.api-key=${GROQ_API_KEY}
assistant.llm.groq.model=openai/gpt-oss-120b
```

Get an API key from [Groq Console](https://console.groq.com/keys). Groq offers free API usage subject to account-specific rate limits; check the current limits in your Groq Console. The previous default, `llama-3.3-70b-versatile`, was deprecated and shut down on August 16, 2026. `openai/gpt-oss-120b` is one of Groq's recommended replacements. Groq uses LangChain4j's OpenAI-compatible chat model and Groq's OpenAI-compatible API URL.

On Windows PowerShell, set the key for the current terminal before starting the app:

```powershell
$env:GROQ_API_KEY = "your-groq-api-key"
.\mvnw.cmd spring-boot:run
```

Alternatively, use Ollama for local inference without a hosted API key; it requires installing Ollama and downloading a model, and generation speed depends on your computer.

### Ollama

```properties
assistant.llm.ollama.enabled=Y
assistant.llm.ollama.base-url=http://localhost:11434
assistant.llm.ollama.model=llama3.1
assistant.llm.ollama.timeout=300s
assistant.llm.ollama.max-retries=5
```

The Ollama request timeout defaults to 300 seconds, with five retries after a failed request (up to six attempts total). Override these with `OLLAMA_TIMEOUT` (for example, `60s`) and `OLLAMA_MAX_RETRIES` (from 0 to 5). A retry starts another full request, so repeated timeouts can keep a chat request open for a long time. Retries are bounded and cannot guarantee success if Ollama is unavailable or the model cannot finish within the timeout. Make sure the selected Ollama model is installed and supports tool calling. Keep API keys in environment variables; do not commit secrets.

## Run

Requires Java 25 and MySQL 8. From Windows PowerShell:

```powershell
.\mvnw.cmd spring-boot:run
```

Run tests with:

```powershell
.\mvnw.cmd test
```

The test profile uses an in-memory H2 database and does not require MySQL or an LLM key.
